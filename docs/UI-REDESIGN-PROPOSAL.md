# 设置界面信息架构方案

> 上游历史资料：本文继承自 HyperDuo，内容对应原项目当时的环境与实现。ColorDuo 面向 ColorOS 15–17（15/16 适配待实机验证）；当前说明见 [ColorDuo 文档索引](README.md) 和 [ColorOS 开发指南](COLOROS17-DEVELOPMENT.md)。

> 2026-10-23。针对当前 2 页 / 1705 行的界面结构，提出重新划分。
> 本文只谈**信息架构与交互**，不含视觉样式（配色、圆角、动效另行讨论）。

---

## 一、现状的事实

**63 个设置项**，由 **27 个滑杆** 和 **19 个开关/选择** 承载，另有布局排序。

当前结构：
```
底部导航： 首页 | 关于

首页（DrawingScreen.kt，1705 行）
  ├ 总开关
  ├ 快速编辑  ── 样式选择 + 场景选择 + 预览
  ├ 组件排序  ── 4~5 个标签页，每页是组件的优先级列表
  ├ 环外组件
  └ 组件外观  ── 15 个卡片的**弹窗列表**
       └ 每张卡片再弹一个 sheet（滑杆 + 开关 + 颜色）
```

## 二、四个具体问题

### 1. 容器参数与容器布局分居两处
胶囊的**布局**在「组件排序 → 左部/右部」，而它的**长度和四个位移**在「组件外观 → 外观」。
改一次胶囊形状要跨两个区块。

### 2. 「外观 / 电池 / 读数」不是组件，却和组件并列
Wi-Fi、电量、闪电是**可放置的组件**；这三张是**全局参数**（容器几何、描边、缩放）。
并列会让用户以为「外观」是某个可以放进槽位的东西。

### 3. 组件设置藏在三层之下
改 Wi-Fi 弧的粗细：组件外观 → Wi-Fi 弧 → 弹窗 → 滑杆。**发现性依赖用户先知道弹窗里有东西**。

### 4. 场景选择器常驻 —— 已撤回

最初列为问题，理由是九个 chip 占了两行，且「危险」和「无 Wi-Fi」要横向滑动才能看到。
**但没有实际困扰支撑**：这两个选择的用途是切换后立刻看预览，收进下拉反而每次多点一次。
而且「收成一行」自己也说不清是下拉、是缩窄、还是分组 —— 一个描述不出具体形态的想法，通常说明它没在解决真问题。
保留在此作为记录，不做。

## 三、方案

### 指导原则

> **摆在哪里** 和 **长什么样** 是两件事，分开。

「组件排序」回答前者，「组件外观」回答后者。全局参数两者都不是，单独安置。

### 新结构：三个页面

```
底部导航： 预览 | 组件 | 设置
```

#### 页面 1：预览（默认）

只放**看**和**摆**。

| 区块 | 内容 |
| --- | --- |
| 总开关 | 保持 |
| 预览 | 放大，占据首屏主要位置 |
| 场景与样式 | 保持现状：两组 chip 各占一行 |
| 组件排序 | 保持现在的标签页结构 |

这一页滚动一次能看到全部，不再需要进第二层。

#### 页面 2：组件

**列出可放置的组件**，点进去改它的尺寸和颜色。

```
Wi-Fi 弧       大小 100%  ›
电量数字       大小 44    ›
充电闪电       大小 100%  ›
网络类型       大小 36    ›
时钟           大小 44    ›
信号点阵       大小 100%  ›
```

每行右侧直接显示**当前值**，点进去是该组件的完整 sheet（现有的 sheet 直接复用）。

关键改变：**不再需要先进「组件外观」再找卡片**。

#### 页面 3：设置

全局参数，按性质分三组：

| 分组 | 内容 |
| --- | --- |
| **容器** | 胶囊长度（仅胶囊时显示）、左右格水平/垂直位移 |
| **外观** | 描边粗细、弧粗细、轨道透明度、角色颜色 |
| **读数** | 整体缩放、性能缩放、字重、环外尺寸与间距 |
| **关于** | 现有的关于页全部内容 |

「容器」这组只在样式为胶囊时出现——**参数跟着它所属的容器走**。

---

## 四、这个方案解决了什么

| 原问题 | 解决方式 |
| --- | --- |
| 容器参数与布局分居 | 容器参数独立成组，且只在胶囊下出现，语义清晰 |
| 「外观」和组件并列 | 分开：组件页只有真组件，全局参数进设置页 |
| 组件设置藏三层 | 组件页一行一个，右侧显示当前值，点进去即改 |
| 首页 1705 行 | 拆成三页，首页只留预览与排序 |

## 五、代价与风险

**这是一次重构，不是美化。** 涉及：

- 底部导航从 2 项变 3 项（`SettingsTab` 枚举、路由、返回栈）
- `DrawingScreen.kt` 1705 行拆分
- 组件设置入口从「弹窗列表」变「页面列表」
- 所有既有用户的肌肉记忆改变——原本两步能到的位置变了

**风险最高的一点**：组件页取代了「组件外观」的弹窗列表，而那个列表同时被**长按组件**的快捷入口复用（`PartSettingsSheet`）。改造时要保证长按仍然能直接开到同一张 sheet，否则会丢掉一个便利入口。

## 六、建议的实施顺序

不建议一次做完。按可独立验证、可独立回退的顺序：

| 步骤 | 内容 | 为什么先做 |
| --- | --- | --- |
| **1** | 容器参数从「外观」移到「组件排序」页底部 | 改动最小，直接验证「容器参数跟着容器走」是否更顺 |
| **2** | 新增「组件」页，把 15 个卡片平铺成列表 | 独立于其他改动，可单独上线 |
| ~~3~~ | ~~场景选择器收成一行~~ | **已撤回**：说不清要解决什么，见 §4 |
| **4** | 底部导航重排为三页 | 已完成（组件页即第二页） |

每步都能单独验证、单独回退。

## 七、需要你先定的三件事

1. **底部导航三项是否接受？** 从「首页/关于」变成「预览/组件/设置」，这是最大的心智改变。
2. **容器参数放哪里？** 我建议跟随容器（只在胶囊样式下出现在排序页），但你之前提过想把它「放出来」——如果指的是独立页面，方案要调整。
3. **`nav_style` / `nav_labels`** 这两个键控制的是**导航栏本身的样式**。在新结构下它们该归「设置 → 外观」，还是继续留在关于页？
